Four contracts (Solidity 0.8.30, OpenZeppelin-based) run the entire protocol. Integrators only need the **MakiDotFun** and **MakiSwapRouter** addresses. Everything else (lockers, treasury, WETH, position managers, factories) is discoverable from the launchpad.

## MakiDotFun

The singleton launchpad and registry, serving both venues: SushiSwap V3 (`venue = 1`) and Uniswap v3 (`venue = 0`).

### Launching

```solidity
function createToken(
    string calldata name,
    string calldata symbol,
    string calldata metadataURI,
    uint256 minTokensOut,
    uint8 venue
) external payable returns (address token);
```

One transaction does everything. It deploys a `MakiToken` (mining a CREATE2 salt so the token sorts above WETH), creates and initializes the WETH/token 1% pool on the chosen venue at the global opening price (`startTick` = 203200), mints the entire 1B supply as a single-sided position spanning `[TICK_LOWER, startTick]` straight into that venue's MakiFeeLocker, and executes the optional dev buy before anyone else can reach the pool. Emits `TokenCreated` (and `DevBuy` if there was one).

`msg.value` must cover the flat creation fee (read it from `feeConfig()`; currently 0.001 ETH); any ETH beyond it is the dev buy, with `minTokensOut` protecting it against front-running. The current global `creatorLpShareBps` is snapshotted into the token's record and never changes afterwards.

The venue is frozen into the token: a token lives on exactly one DEX, forever. And because no liquidity exists above `startTick`, the opening price is a permanent floor. See [direct listing](/protocol/direct-listing) and [venues](/protocol/venues).

The registry is shared: launches on both venues sit in one list, in launch order. `getTokenInfos` batches whole listing pages into one call.

### Fees

```solidity
function setFeeRecipient(address token, address newRecipient) external; // current recipient only
function claimProtocolFees() external;                                  // treasury only; pays accrued creation fees
```

**Fee model:** there is **no per-trade launchpad fee**. Creator and protocol revenue is the pool's own 1% swap fee accruing to the locked position, harvested through the venue's FeeLocker (below) and split at the token's snapshotted `creatorLpShareBps` (3000 bps to the creator under the current config). The launchpad itself only collects the flat creation fee. The global `feeConfig` is owner-tunable within a hard cap (`MAX_CREATION_FEE` = 0.1 ETH), and applies to future launches only. See [fees](/protocol/fees).

### Owner surface (complete list)

```solidity
function setFeeConfig(FeeConfig calldata c) external;   // future launches only; hard-capped
function setClaimAuthority(address a) external;         // rotate/disable the backend claimer
function setTreasury(address newTreasury) external;
function setLocker(uint8 venue, address locker_) external; // one-time per venue, consumed at deployment
```

Ownership is two-step (`transferOwnership` / `acceptOwnership`). There is deliberately no withdraw, pause, upgrade, seize, or retroactive fee-change function. See [security](/protocol/security).

### Events

```solidity
event TokenCreated(address indexed token, address indexed creator, address indexed pool,
                   uint256 positionId, string name, string symbol, string metadataURI,
                   uint16 creatorLpShareBps, uint8 venue);
event DevBuy(address indexed token, address indexed creator, uint256 ethIn, uint256 tokensOut);
event FeeRecipientSet(address indexed token, address indexed recipient);
event FeeConfigSet(uint16 creatorLpShareBps, uint96 creationFee);
event LockerSet(address indexed locker, uint8 venue);
event ProtocolFeesClaimed(address indexed treasury, uint256 amount);
event TreasurySet(address indexed treasury);
event ClaimAuthoritySet(address indexed authority);
```

These are all launch-time and admin events. Trading happens on the pool, which the launchpad never sees; for trades, watch `Swap` on each token's pool (`TokenCreated.pool`).

## MakiToken

The per-launch ERC-20, deployed by `createToken`:

- OpenZeppelin `ERC20` + `ERC20Permit` (EIP-2612), 18 decimals
- Fixed supply of 1,000,000,000 × 1e18, minted once at launch and placed entirely into the locked position
- `metadataURI()`: immutable token metadata pointer (e.g. `ipfs://…`)
- **No** owner, mint, burn-by-admin, pause, blacklist, or fee-on-transfer

## MakiFeeLocker

One per venue, byte-identical: an immutable, ownerless vault holding every launch's LP position forever. Both lockers read their fee config back from the launchpad, so the two share one treasury and one claim authority.

```solidity
function positionOf(address token) external view returns (uint256 tokenId); // 0 = not launched here
function collectFees(address token) external returns (uint256 amount0, uint256 amount1);
    // fee recipient, treasury, or claimAuthority only
```

The locker has no function that can transfer a position out; locked liquidity is permanent by construction. Each harvest collects the whole position's accrued 1% swap fees at once and splits them creator/treasury at the token's launch-time snapshot, read live from the launchpad's `creatorLpShareBpsOf(token)` (30/70 under the current config). One call always pays both parties. Emits `FeesCollected` per harvest and `PositionLocked` at launch.

## MakiSwapRouter

Uniswap v3 has a SwapRouter02 on this chain; Sushi does not (RedSnwapper needs off-chain route bytes that don't exist for a pool seconds old). MakiSwapRouter swaps directly against the pool with its own callback: identical on both venues, live the instant the pool exists, native ETH in and out. It is stateless, ownerless, and immutable, and it only swaps against a pool it re-derived from a known factory, so a hostile address can't be passed off as a pool.

```solidity
function buy(address pool, uint256 minTokensOut, uint256 deadline)
    external payable returns (uint256 tokensOut);    // msg.value = ETH in

function sell(address pool, uint256 tokenAmount, uint256 minEthOut, uint256 deadline)
    external returns (uint256 ethOut);               // requires prior approve of the router

event Swap(address indexed pool, address indexed trader, bool indexed isBuy,
           uint256 amountIn, uint256 amountOut);
```

Errors: `UnknownPool`, `NotWethPool`, `Expired`, `SlippageExceeded`, `ZeroAmount`, `NotPool`, `OnlyWeth`, `EthTransferFailed`, `ZeroAddress`

The router's `Swap` event is trader-indexed, which makes per-wallet activity scans cheap. It only covers trades routed through Maki; the pool's own `Swap` event is the complete record.
