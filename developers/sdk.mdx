`@maki-studio/sdk` is the official TypeScript SDK for the maki.finance protocol. It's a thin, fully-typed layer over [viem](https://viem.sh) (its only peer dependency) covering the entire protocol surface: launching tokens, trading against the launch pool, quoting, fee claims, and event streaming.

```bash
npm install @maki-studio/sdk viem
```

<Info>
  The package ships both ESM and CommonJS builds (`import` and `require` both work). All amounts are `bigint` wei values. Use viem's `parseEther` / `formatEther` helpers.
</Info>

Three protocol facts shape the API:

- **Two venues, one registry.** `Venue.SUSHI` (1) and `Venue.UNISWAP` (0) are canonical v3 forks sharing one WETH, both on the 1% tier, so a launch opens on identical geometry either way and the same quote math serves both. The venue is frozen into the token at creation; there is a single launchpad, a single `TokenCreated` stream, and a single fee ledger.
- **The launchpad does not intermediate trades.** After launch, trading is an ordinary v3 swap. `write.buy` / `write.sell` go through MakiSwapRouter straight against the pool, with native ETH in and out.
- **The opening price is a permanent floor.** No liquidity was ever minted above `startTick`, so a sell can never push the price above the launch price. `quoteSell` reports this as `cappedAtOpeningPrice` rather than pretending the fill exists.

## Setup

Create a viem client pair and pass it to `createMaki`. The SDK exports ready-made chain definitions for Robinhood Chain mainnet and testnet.

```ts
import { createPublicClient, createWalletClient, http, parseEther } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { createMaki, robinhoodMainnet } from "@maki-studio/sdk";

const publicClient = createPublicClient({
  chain: robinhoodMainnet,
  transport: http(),
});

const walletClient = createWalletClient({
  chain: robinhoodMainnet,
  transport: http(),
  account: privateKeyToAccount(process.env.PRIVATE_KEY as `0x${string}`),
});

const maki = createMaki({
  publicClient,
  walletClient, // optional; omit for read-only usage
  network: "mainnet",
});
```

<Warning>
  Only `"mainnet"` is deployed. The `"testnet"` entry is a guarded placeholder (neither DEX exists on Robinhood Chain testnet); the SDK throws a descriptive error if you select it. For development, fork mainnet with Anvil and pass a custom deployment object (below).
</Warning>

Three namespaces do all the work:

- `maki.read`: typed views over the launchpad (registry, launch records, fee config, launch geometry, venue discovery, pool state)
- `maki.write`: transactions (throws if you didn't pass a `walletClient`)
- `maki.watch` / `maki.backfill`: event streaming and historical indexing

<Note>
  **Local development:** you can point the SDK at any deployment (e.g. an Anvil fork) by passing a deployment object instead of a network name:
  ```ts
  const maki = createMaki({
    publicClient,
    walletClient,
    network: { chain, launchpad: "0x…", swapRouter: "0x…", deployBlock: 0n },
  });
  ```
</Note>

## Launching a token

One transaction deploys the ERC-20, opens the WETH/token 1% pool on the chosen venue at the global opening price, locks the entire 1B supply as a single-sided position in that venue's fee locker, and optionally executes the creator's dev buy before anyone else can reach the pool. The flat creation fee (0.001 ETH under the current config) is read live and added to the transaction value automatically, so `devBuyEth` is exactly the dev buy.

The token address is not knowable in advance (the CREATE2 salt is mined on-chain so the token sorts above WETH), so `launch` waits for the receipt and decodes it for you:

```ts
import { Venue } from "@maki-studio/sdk";

const { token, pool, venue, positionId, devBuyTokensOut } = await maki.write.launch({
  name: "Maki Star",
  symbol: "MAKI",
  metadataURI: "ipfs://Qm…",       // image + description, pinned to IPFS
  venue: Venue.SUSHI,              // or Venue.UNISWAP
  devBuyEth: parseEther("0.5"),    // optional first buy, before the public
});
```

`maki.write.createToken(params)` is the lower-level variant: same parameters, returns just the transaction hash.

<Note>
  Every `maki.write.*` method **simulates first** (so reverts are decoded before you spend gas) and returns the transaction `Hash` (`launch` is the one exception; it awaits the receipt for you). Await confirmation with `publicClient.waitForTransactionReceipt`.
</Note>

## Reading the protocol

```ts
// Enumerate launches (newest last; both venues in one list, in launch order),
// then batch-fetch launch records in one RPC call
const tokens = await maki.read.getTokens(0n, 50n);
const records = await maki.read.getTokenRecords(tokens);
// each → { creator, creatorLpShareBps, venue, pool, positionId }

// Per-token views
const record = await maki.read.getTokenRecord(token);
const meta = await maki.read.getTokenMetadata(token);
// → { address, name, symbol, metadataURI }

// Live pool state, feed straight into the quote math
const state = await maki.read.getPoolState(record.pool);
// → { sqrtPriceX96, tick, liquidity }

// The GLOBAL fee config (owner-tunable; what FUTURE launches will snapshot).
// For a specific token's split, use its record; that never changes.
const { creatorLpShareBps, creationFee } = await maki.read.getFees();

// The immutable opening geometry, identical on both venues
const geometry = await maki.read.launchGeometry();
// → { startTick, startSqrtPriceX96, tickLower, tickSpacing, poolFee }

// Per-venue infrastructure, all discovered from the launchpad
const venues = await maki.read.venues();
// → [{ venue, positionManager, factory, locker }, …]
const locker = await maki.read.lockerFor(token); // the locker holding this token's position
```

## Quoting

Quotes are computed **client-side, with zero RPC round-trips**. The `math` module is an exact port of Uniswap's `TickMath` plus single-range v3 swap math with the pool's own rounding, and it's venue-independent: both DEXes are canonical forks on identical launch geometry. A fork test in the contracts repo pins parity, asserting a live 1 ETH buy fills for exactly the wei amount `quoteBuy` returns, on both venues.

```ts
import { quoteBuy, quoteSell, priceInWei, fdvWei, soldProgressBps } from "@maki-studio/sdk";

const state = await maki.read.getPoolState(pool);

const q = quoteBuy(state, parseEther("1"));
// → { tokensOut, fee, ethUsed, sqrtPriceX96After }

const sq = quoteSell(state, tokensIn);
// → { ethOut, fee, tokensUsed, sqrtPriceX96After, cappedAtOpeningPrice }

const price = priceInWei(state.sqrtPriceX96);  // wei per whole token
const fdv = fdvWei(state.sqrtPriceX96);        // wei, over the fixed 1B supply
const sold = soldProgressBps(state);           // 0–10000: how much of the position buyers hold
```

<Info>
  `cappedAtOpeningPrice: true` means the sell would push the price up to the launch price, where liquidity ends. `tokensUsed` is then less than the input: the rest has nowhere to trade. Surface this in your UI instead of quoting a fill that can't happen.
</Info>

## Trading

Trades go through MakiSwapRouter straight against the token's own pool: native ETH in and out, identical on both venues, live from the block the token launched in. Pass the pool address (from the token's record or `TokenCreated.pool`) plus your quote; slippage (default 1%) and deadline (default 5 min) are built in.

```ts
// Buy: exact ETH in
const q = quoteBuy(await maki.read.getPoolState(pool), parseEther("1"));
const hash = await maki.write.buy(pool, parseEther("1"), q.tokensOut, { slippageBps: 100 });
await publicClient.waitForTransactionReceipt({ hash });

// Sell: approve the router once, then swap
await maki.write.approveRouter(token, amount);
const sq = quoteSell(await maki.read.getPoolState(pool), amount);
await maki.write.sell(pool, amount, sq.ethOut, { slippageBps: 50 });
```

Check an existing allowance with `maki.read.swapAllowance(token, owner)` to skip the approve when it's already in place.

## Claiming fees

There is no per-trade launchpad fee. Creator and protocol revenue is the pool's own 1% swap fee accruing to the locked position, harvested through the venue's FeeLocker and split creator/treasury at the token's snapshotted `creatorLpShareBps` (30% to the creator under the current config). Claims are gated but never redirect funds: one call always pays both parties.

```ts
// Harvest a token's locked-LP swap fees. Resolves the right venue's locker itself.
// Callable by the token's fee recipient, the treasury, or the claim authority.
await maki.write.collectFees(token);

// Redirect your fee stream (only the current recipient can call this)
await maki.write.setFeeRecipient(token, "0xNewRecipient…");

// Accrued creation fees; treasury only
await maki.write.claimProtocolFees();
```

Every launched token is an `ERC20Permit`, and `maki.write.signPermit({ token, spender, value })` produces the `{ v, r, s, deadline }` tuple for approve-free integrations.

## Streaming events

The watch layer polls `eth_getLogs` over HTTP (Robinhood Chain's public RPC has no websocket), delivers events **at least once** in `(blockNumber, logIndex)` order, and gives you a cursor for crash-safe resumption:

```ts
const stop = maki.watch(
  {
    onTokenCreated: (e) => index(e.token, e.pool, e.venue),
    onDevBuy: (e) => console.log("dev bought", e.tokensOut),
    onBlockProcessed: (n) => saveCursor(n), // persist this; it's your resume point after restarts
    onError: (err) => console.error(err),
  },
  { fromBlock: await loadCursor(), pollIntervalMs: 1000 },
);

// later: stop()
```

For historical indexing, `backfill` replays the full event history in chunked `eth_getLogs` calls and resolves with the last processed block:

```ts
const lastBlock = await maki.backfill({ onTokenCreated: indexToken });
```

Handlers exist for every launchpad event: `onTokenCreated`, `onDevBuy`, `onFeeRecipientSet`, `onFeeConfigSet`, `onProtocolFeesClaimed`, `onLockerSet`.

<Info>
  The launchpad only emits **launch-time** events. Once a token is created, all trading happens on its v3 pool, which the launchpad never sees. For a live trade feed, subscribe to `Swap` on each token's own pool (`TokenCreated.pool` is the address). MakiSwapRouter emits its own trader-indexed `Swap` too, but only for trades routed through it; the pool's event is the complete picture.
</Info>

```ts
import { parseAbiItem } from "viem";

const unwatch = publicClient.watchEvent({
  address: pool, // from TokenCreated.pool
  event: parseAbiItem(
    "event Swap(address indexed sender, address indexed recipient, int256 amount0, int256 amount1, uint160 sqrtPriceX96, uint128 liquidity, int24 tick)",
  ),
  onLogs: handleTrades,
});
```

Make handlers **idempotent** (delivery is at-least-once), and key trades on `transactionHash + logIndex` in your database.

## Error handling

Writes simulate first, so contract reverts surface as decoded errors before gas is spent. The custom errors you'll most commonly handle:

| Error | Meaning |
| --- | --- |
| `SlippageExceeded` | Price moved past your `slippageBps`; re-quote and retry |
| `Expired` | The `deadline` passed before inclusion |
| `UnknownPool` | The pool is not a launch pool derivable from a known factory |
| `UnknownToken` | Address is not a maki.finance launch |
| `InsufficientCreationFee` | `createToken` value didn't cover the flat fee (the SDK adds it for you) |
| `UnknownVenue` | Venue id is neither 0 (Uniswap) nor 1 (Sushi) |
| `NotFeeRecipient` | `setFeeRecipient` from a non-recipient address |
| `NotAuthorized` | `collectFees` from an address that is not the recipient, treasury, or claim authority |
| `ZeroAmount` | Trade amount was zero |
